Обычный запуск ноутбуков

Работать в отдельной копии репозитория: выходные data/, checkpoints/, results/
не должны содержать артефакты другого запуска. Исходные результаты не перезаписывать.
Python 3.12. Установка в своё окружение из корня репозитория:
  python -m pip install -r requirements-experiments.txt
  python -m pip install --no-deps -e .
  python -m pip install jupyterlab
  python -m jupyter lab
Выбрать ядро этого же Python. Ноутбуки подготовки запускать из notebooks/.
Для повторения CUDA-окружения установить torch2.6.0 из индекса cu124 PyTorch.

Для каждого датасета подготовить исходные Amazon Reviews2014 5-core и metadata:
  Beauty: data/Beauty/Beauty_5.json, data/Beauty/metadata.json
  Toys: data/Toys/Toys_and_Games_5.json, data/Toys/metadata.json
  Sports: data/Sports/Sports_and_Outdoors_5.json, data/Sports/metadata.json
Файлы должны быть распакованы из .gz; URL указаны в DatasetProcessing.

Порядок ячеек/ноутбуков сверху вниз, Restart Kernel and Run All:
  1. DatasetProcessing.ipynb для Beauty, DatasetProcessingToys/Sports.ipynb для остальных.
     Выходы: inter.json, item_texts.parquet, items.parquet.
  2. EnrichmentV2Beauty/Toys/SportsLocal.ipynb.
     Выход: data/<dataset>/enrichment/enriched_v2/summaries.parquet.
     Qwen2.5-7B-Instruct, фиксированный revision, BF16, batch128.
     Исходная генерация Toys/Sports использовала A100; обычная 1080Ti этот режим не поддерживает.
  3. ContentEmbeddingsBeauty/Toys/SportsLocal.ipynb.
     Читает исходные тексты и summaries.parquet из шага2.
     Выходы: content_embeddings_original.pkl, content_embeddings_enriched_v2.pkl.
     Llama7B, фиксированный revision, FP32, eager attention, masked mean, max_length1024, batch1.
     Веса FP32 требуют около28GB памяти; device_map=auto может распределять их междуGPU/CPU.
  4. RQVAEBeauty/Toys/Sports.ipynb: обучение original, inference semantic IDs,
     обучение enriched_v2, inference semantic IDs.
  5. TIGERBeauty/Toys/Sports.ipynb: обучение original и enriched_v2, seed42.
     Они вызывают те же Python-скрипты, что и проведённые эксперименты, в отдельных процессах.
     Для других seed использовать существующие train_*_seedNN.py; настройки находятся в коде.
     Все три датасета автоматически сохраняют results/*_test.json на лучшем validation-чекпоинте.


Slurm, SSH, S3, переменные окружения с параметрами модели для этих ноутбуков не нужны.
На ИТМО Slurm выделяет ресурсы для проверки; он не подставляет параметры в ячейки.

В корне снимка сохранены исходный Git bundle (6cbe89e), окружения,
final_rows.json, final_stats.json и квитанции *_VERIFIED.json.
SNAPSHOT_COMPLETE.json подтверждает завершение копирования и проверки.
Это защита от случайной перезаписи, а не независимая резервная копия хранилища.

Где следить за текущей проверкой на ИТМО:
  reproduction/checks/baseline-summary.json — исходные ноутбуки, по два запуска;
  reproduction/checks/candidate-summary.json — обновлённые ноутбуки, по два запуска;
  reproduction/checks/training-state.json — этапы RQVAE/TIGER и сравнения;
  reproduction/executed/ — выполненные ноутбуки с выводами;
  reproduction/IRec/tensorboard_logs/ — новые кривые обучения.
Внутри обучения используются обычные вызовы Python из ноутбуков.
Внешний проверяющий процесс только выполняет ячейки и сравнивает артефакты.
Проверка отдельных этапов на сохранённых эмбеддингах не доказывает,
что Qwen/Llama повторно выдают те же описания и эмбеддинги.
